# 방향

원고지 코드 에디터가 무엇을 목표로 하고, 어떤 판단을 이미 내렸고, 무엇이 아직 열려 있는지.

## 목표

**블록코딩만큼 쉬운 텍스트코딩.**

블록코딩이 쉬운 이유를 분해하면 다섯인데, 넷은 텍스트 에디터도 가질 수 있다.

|                            | 텍스트에서             |
| -------------------------- | ---------------------- |
| 철자를 틀릴 수 없다        | 자동완성               |
| 뭘 할 수 있는지 보인다     | 팔레트                 |
| 구조가 형태로 보인다       | 원고지 격자 + 들여쓰기 |
| 실험이 안전하다            | undo                   |
| **문법 오류가 불가능하다** | 이 문서의 주제         |

마지막 하나를 한 겹 더 파면 이렇다 — Scratch가 쉬운 건 오류 메시지가 친절해서가 아니라 **깨진 중간 상태가 아예 없어서**다. 매 순간 프로그램이 구조적으로 유효하다. 텍스트 편집은 반대로 대부분의 순간이 깨져 있고 가끔 유효해진다. `만약 나이 >` 까지 친 순간이 그렇다.

## 원칙

> **구조는 유효하게, 잎은 자유롭게.**

구조 편집(블록 이동, 조건절 추출, 반복문으로 감싸기)은 유효한 상태에서 유효한 상태로 건너뛴다. 값 편집(숫자, 문자열, 이름)은 타이핑이지만, 잎을 고치는 건 구조를 깨지 못한다. 최악이 틀린 값이지 파싱 오류가 아니다.

이 원칙 덕에 목표가 달성 가능해진다. "모든 순간이 유효"를 글자 단위로 요구하면 아무것도 칠 수 없다.

## 커서는 지점이지 칸이 아니다

편집 위치를 '칸'으로 보고 박스를 그리려다 실패했다. 이유는 근본적이다.

**글자는 N개인데 삽입 지점은 N+1개다.** 커서는 글자 *사이*에 있으므로 칸으로 투영하는 전사 함수가 존재하지 않는다. 시도했을 때 나온 특수 케이스가 전부 경계 아티팩트였다.

| 케이스                   | 왜 필요했나                                   |
| ------------------------ | --------------------------------------------- |
| `col === 0`              | 줄 첫 칸엔 "이전 글자"가 없음                 |
| trailing whitespace 보정 | 공백 다음 지점이 공백 칸으로 투영되는 게 어색 |
| 문서 맨 끝               | head 자리에 글자가 없음                       |
| 빈 줄                    | 글자가 아예 없음                              |
| 조합 중 `head - 1`       | 같은 투영의 방향 모호성                       |

그래서 **타이핑 중 커서는 지점**이다. CM6의 `drawSelection()`이 그리는 캐럿을 쓰고, 격자 칸에 맞춰 세로로 꽉 차게 한다.

박스가 틀린 게 아니라 **모드가 틀렸다.** 스프레드시트는 셀 선택이 박스, 편집 시작하면 안에 캐럿이다. Vim은 normal이 블록, insert가 막대다. 박스는 **구조 편집 모드**의 것이다.

## Draft-Apply 모델 (검토 중)

스니펫에서 구문을 고르면 draft 세션이 열리고, 그 구문에 해당하는 영역만 활성화되고 나머지는 흐려진다. 필드를 다 채우면 세션이 닫히고 반영된다.

**draft는 에디터 전용이다.** 파일에 저장되지 않는다. 대안(구멍을 언어의 일급 토큰으로 만들기)은 문법을 건드리므로 훨씬 무겁다.

**draft는 스택이다.** 조건식 안에서 함수 호출을 쓰면 그 호출이 자기 세션을 push하고, 인자를 다 채우면 pop해서 바깥 세션으로 돌아온다. 중첩이 엄격하게 포개지므로 스택으로 충분하다.

IME 조합이 이미 같은 구조다. `ㅇ → 아 → 안`이 draft고 확정이 apply다. 한국어 사용자에게는 설명이 필요 없는 멘탈모델이다.

### 열린 질문

**1. 세션 종료 조건.** "완성되면 자동 pop"은 너무 일찍 pop한다. `만약 나이 ▢ 이면`의 구멍에 `나이`만 쳐도 이미 완결된 식(변수 참조)이라 `나이 >= 20`을 치기 전에 닫힌다. 유효한 식의 프리픽스가 그 자체로 유효한 경우가 흔하다 — `f`, `나이 + 1`, `길이(목록)`.

→ pop은 **명시적(Tab/Enter)**이어야 하고, 유효성은 "Tab이 먹는 조건"이라는 게이트로 쓴다. 보장은 유지되면서 조기 종료가 없어진다.

**2. 수정 경로.** 이 모델은 작성만 다룬다. 이미 반영된 조건식을 클릭해서 고치는 순간 보장이 사라진다. 그리고 편집 시간의 대부분은 수정이다.

→ 반영된 코드를 건드리면 그 구문의 draft로 재진입시키면 모델이 일관되나, "클릭만 해도 모드가 바뀐다"의 체감을 봐야 한다.

**3. 보장의 정확한 범위.** 구멍 안에서 `나`, `나이 `, `나이 >`는 여전히 무효한 식이다. 보장은 "틀린 문법이 될 수 없다"가 아니라 **"구조적으로 무효한 상태가 없다"**이다. 표현이 느슨하면 나중에 흔들린다.

**4. 탈출구.** draft 중에 다른 곳을 고치고 싶으면? Esc를 누르면 반쯤 쓴 구조는 어떻게 되나? editor-only라 구멍을 저장할 수 없으므로 지우거나 강제 커밋뿐이고, 둘 다 놀라운 동작이다. 모달 시스템이 미움받는 전형적인 지점.

**5. 흐림의 비용.** 3단계 중첩이면 화면 대부분이 흐려진다. 조건을 쓰려고 위에 정의한 변수 이름을 참조하려는데 그게 흐려져 있으면 곤란하다.

### 이 장르가 실패하는 방식

프로젝셔널 에디터(MPS 계열)가 반복해서 죽은 이유는 **쉬운 80%를 쉽게 만들고 나머지 20%를 불가능하게 만들어서**다. 생각한 걸 그냥 칠 수 없는 순간 사람들이 떠난다.

우리에게 유리한 점이 둘 있다.

- **언어를 소유한다.** 범용 에디터는 모르는 N개 언어를 지원해야 해서 키를 거를 수 없다. 여기서는 언어·토크나이저·에디터·대상 사용자가 전부 한 손에 있다.
- **저장 형식이 텍스트다.** 제약이 형식이 아니라 에디터에만 있다. 답답하면 메모장으로 열어 고치면 된다. MPS는 저장 형식 자체가 트리라 탈출구가 없었다.

그러니 검증해야 할 첫 질문은 "틀릴 수 없나"가 아니라 **"막혔을 때 답답한가"**다. 전자는 만들면 되고 후자는 만들어봐야 안다.

## 확정된 기술 선택

### CodeMirror 6

문서 모델은 닫혀 있고 뷰는 열려 있다. 이 기획은 뷰가 이상하고(격자, 칸 글로우) 모델은 평범한 문자열이라 방향이 맞물린다.

`textarea`는 자기 텍스트를 스타일링할 수 없어 blend 레이어 스택으로 우회해야 했고, 프로그램 편집이 들어오는 순간 `execCommand`(후계자 없는 deprecated API)에 목을 매게 된다. 멀티 사이트 편집이 하나의 undo로 묶이지 않는 것도 확인했다 — 조건절 추출 같은 리팩터링이 절반만 되돌려진다.

Lezer 문법은 작성하지 않는다. 자체 토크나이저가 `{type, value, position}`을 주므로 `Decoration.mark`로 바로 변환한다. `autocompletion({ override: [...] })`로 언어 데이터 경로를 건너뛴다.

### 정방형 폰트

`editor/font/build.py`가 만든다. 한글은 Interlude, ASCII·기호는 JetBrains Mono Nerd Font에서 가져와 **모든 글리프의 advance를 1em으로 통일**한다.

이것이 성립시키는 것:

- 격자가 `background-size: 1ch 1lh` 한 줄
- 문자 위치에 UI를 붙이는 게 `left: ${col}ch` 산수. `range.getClientRects()` 측정이 필요 없다
- 드롭 타겟이 칸 경계라 이산적이고 크다 — Scratch 블록이 잘 스냅되는 것과 같은 성질

`tab-size: 1`을 함께 쓴다. 미적인 이유가 아니라 **문자 인덱스 == 칸 번호** 불변식이 유지되기 때문이다. `tab-size: 4`면 오버레이·팝업·오류 표시가 전부 탭 확장을 거쳐야 한다.

### 격자의 한계

**이모지와 조합형 한글은 이 등식을 깬다.** 측정 결과:

```
가 (완성형 U+AC00)   length 1, 1.00칸
가 (조합형 NFD)      length 2, 1.00칸    ← 2 코드유닛이 1칸
🎉                   length 2, 1.25칸    ← 폴백 폰트
```

이모지를 지원한다면 `col`을 코드유닛이 아니라 grapheme 클러스터로 세야 한다(`findClusterBreak`). 붙여넣기를 NFC로 정규화하면 조합형 한글은 없앨 수 있다. 이모지는 폰트에 없어 폴백되므로 칸 자체가 안 맞는다.

## 알려진 업스트림 버그

둘 다 작업을 막지는 않는다.

**Deno LSP** — `deno.json`이 `package.json`보다 상위 디렉터리에 있으면 같은 npm 패키지를 두 모듈 정체성으로 해석한다. `private` 필드를 가진 클래스(`SelectionRange`, `EditorState`)가 경계를 못 넘는다. `deno check`는 정상이고 LSP만 영향받는다.

→ 워크어라운드: 최상위 `deno.json`의 import map에 명시. `denoland/deno#36664`

**CodeMirror** — 전체 선택 상태에서 IME 조합을 시작하면 Firefox가 contenteditable을 텍스트 노드 하나로 붕괴시키고, `getCompositionContext`가 `line: null`을 반환하는데 `addComposition`이 널 검사 없이 역참조한다. Chrome은 정상. 6.40.0 이래 해당 코드가 바뀌지 않았으므로 회귀가 아니다.

→ 리포트 작성됨, `codemirror/dev`에 미제출.

## 다음

우선순위 순.

1. **읽기 전용 오버레이 먼저.** 문법색, 오류 강조, 칸 글로우, 툴팁. 전부 텍스트를 건드리지 않으므로 망가질 게 없다.
2. **스니펫 + 구멍.** 팔레트가 텍스트가 아니라 뼈대를 넣는다. CM6 `snippetCompletion`이 Tab 이동까지 제공한다. 강제 없이 길만 깔고 사람들이 그 길로 가는지 본다.
3. **Draft-Apply.** 위 열린 질문들이 정리된 뒤. 특히 세션 종료 조건과 수정 경로.
4. **블록 DND.** AST 노드 단위. 멀티 사이트 편집이 하나의 트랜잭션이므로 undo가 정확하다.

## 강제에 대하여

뼈대와 자동완성은 **기능**이고, 뼈대 경로 밖으로 못 나가게 막는 것은 **강제**다. 둘을 섞어 논하지 않는다.

기능은 논쟁거리가 아니다. 고도로 제약된 언어에 맞춰진 자동완성은 환영받는다.

강제가 성립하는 조건은 하나다 — **후보 집합이 완전할 것.** 범용 언어에서 강제가 죽는 이유는 하고 싶은 걸 제안하지 못해서지 강제 자체가 나빠서가 아니다. 약속은 구조 층의 후보가 유한하고 열거 가능하므로 이 조건을 만족할 수 있다.

```
구조 (유한, 열거 가능)          →  강제해도 막히는 것이 없음
잎   (이름, 숫자, 문자열: 무한)  →  자유
```

그래서 검증할 질문은 "사람들이 좋아하는가"가 아니라 이것이다.

> **팔레트로 만들 수 없는 유효한 약속 프로그램이 존재하는가?**

하나라도 있으면 거기서 강제가 사람을 가둔다. 문법을 훑어 기계적으로 확인할 수 있고, 사용자 관찰이 필요 없다.

### 타이핑 경로도 draft 를 연다

팔레트로만 draft 가 열리면 익숙해진 사용자에게는 팔레트가 타이핑보다 느리다. `만약 ` 를 치는 편이 목록을 열고 고르는 것보다 빠르다. 그러면 숙련자는 팔레트를 피하고, 피하는 순간 보장 밖으로 나간다.

```
팔레트에서 만약 선택   →  draft 열림
"만약 " 타이핑         →  draft 열림
```

둘 다 같은 곳으로 가야 한다. 초보자는 팔레트로, 숙련자는 타이핑으로, 둘 다 같은 보장 안에서.
